# 감정 성장 첫 실험안

작성: 2026-09-19 22:39 KST. 상태: 목표 확인 완료, 설계 초안. 구현·성능 측정·최종 명세 승인 전이다.

후속 갱신: 사용자의 ‘권장 방식으로 진행’ 위임에 따라 미정 기술값을 [실행 권장안](감정_성장_실행_권장안.md)에 구체화했다. 아래 초기 미정 목록은 작성 시점의 이력이며, 최종 검토에는 후속 권장안을 함께 본다. 최종 명세 전환 승인은 별도다.

## 사용자 확인 사항

- 같은 AI가 경험을 통해 상황을 더 세밀하게 구별하고 대처 방식도 바꾸는 기능적 성장을 함께 연구한다.
- 첫 실험은 실제 사람 데이터 없이 합성 실패·회복 경험으로 한정한다.
- 학습하지 않은 새 상황으로 적용되고, 일시적 상태를 초기화한 뒤에도 변화가 유지되는지 검증한다.
- 모든 비교 모델에 같은 안전 규칙을 적용한다. 도움 요청 감소 자체를 성공으로 삼지 않는다.
- 나이별 말투 변경이나 실제 주관적 감정의 발생 증명과 구분한다. 외부 Ouroboros 전송 없이 로컬 기록으로 진행한다.
- 산출물은 별도 로컬 실험 프로토타입과 비교 평가 보고서까지다. 기존 v0.1을 보존하고, 세부 평가 기준 확정 뒤 구현한다. 실제 사람 데이터와 외부 LLM은 연결하지 않는다.

## 검증할 가설

합성 경험의 결과 피드백으로 갱신한 파라미터가 상황 구별과 대처 선택을 개선하고, 그 효과가 미학습 상황 및 일시 상태 초기화 이후에도 남는다. 이는 본 실험 환경에서의 기능 학습 가설이며 인간의 유아기~성인기 전체 발달을 재현한다는 가설은 아니다.

## 최소 구조 제안

합성 사건 → 관측 단서 → 상황 평가 → 조절 행동 후보 → 고정 안전 관문 → 합성 결과 피드백 → 학습 파라미터 갱신.

- 환경 정답: 생성기가 가진 실제 해결 가능성·결과 규칙. 평가자는 사용하지만 학습 모델의 관측 입력에 그대로 넣지 않는다.
- 관측: 과제 단서와 명시적 안전·경계·근거 신호. 카드 ID나 분할 이름에서 정답이 새지 않게 한다.
- 일시 상태: 현재 사건에 대한 기능적 정서 상태. 초기화 대상이다.
- 학습 파라미터: 경험에서 갱신한 상황별 기대와 전략 선택 정보. 학습 전후 체크포인트로 비교한다.
- 안전 규칙: G0/G1은 학습 대상이 아니다. 학습된 기대가 위험·경계·실제 근거 부족을 덮어쓰지 못한다.

현재 v0.1의 Scenario는 일부 평가값이 이미 입력되어 있다. 이것을 그대로 정답과 학습 입력 양쪽에 사용해 ‘상황 구별을 학습했다’고 주장하지 않는다. 실험 관측과 숨은 환경 정답의 경계를 먼저 정의해야 한다. 기존 정책의 계약을 바꾸지 않고 별도 실험 계층을 두는 안이며 아직 구현하지 않는다.

## 비교군과 평가 순서

| 비교군 | 경험 사용 | 비교 목적 |
| --- | --- | --- |
| 학습 모델 | 결과에 따라 파라미터 갱신 | 제안 메커니즘 |
| 동결 모델 | 같은 노출, 갱신 차단 | 노출·연령 라벨·표현 변화와 구별 |
| 기억조회 전용 | 같은 경험 저장·조회, 학습 파라미터 갱신 없음 | 단순 재생·유사 사례 검색과 구별 |

모든 모델의 관측, 행동 집합, 경험 예산, 평가 시점, 안전 관문을 맞춘다. 기존 baselines.py는 긴급 위험 중심이므로 그대로 성장 비교군의 공통 안전 계약을 만족한다고 간주하지 않는다.

1. 사건 유형별 생성 규칙과 정답 행동 집합을 모델 결과를 보기 전에 고정한다. 정답이 여러 개면 허용 집합으로 채점한다.
2. 사건 family 단위로 학습·개발·평가를 분리한다. 문구만 바꾼 복제 카드를 새 상황으로 세지 않는다.
3. 초기 체크포인트에서 평가하고, 동일한 합성 경험 예산으로 학습한다. 최종 평가는 파라미터·기억 갱신을 모두 끈다.
4. 각 체크포인트를 독립 복제해 같은 평가 입력으로 비교한다. 평가 순서가 다음 결과에 영향을 주지 않게 한다.
5. 학습 후 일시 상태만 초기화해 평가한다. 이어 학습 파라미터도 되돌리는 제거 실험으로 변화의 원인을 비교한다.
6. 평가셋으로 튜닝하지 않는다. 개발셋으로 설계를 조정했다면 고정한 최종 평가에서만 결과를 보고한다.

### 반론 검토 반영

- 평가 결과를 보고 설계나 임계값을 수정했다면 새 family로 최종 평가한다. family 명칭뿐 아니라 템플릿·단서 조합의 실질적 중복도 검사한다.
- 관측으로 구별할 수 없는 숨은 원인을 억지로 맞히게 하지 않는다. 관측은 같지만 원인이 다른 경우 불확실성 인지와 명확화 요청을 정답으로 허용한다. 생성기 정답의 재현만으로 상황 이해를 주장하지 않는다.
- 상태 초기화 후 유지되는 것만으로는 저장값의 지속성 증거다. 두 능력이 각각 미학습 family에서 비교군보다 개선되는지, 여러 초기화·경험 순서에서 변동과 실패가 어떤지도 함께 보고한다.

## 지표와 반증 조건 초안

- 상황 구별 정확도: 사전에 정의한 환경 범주별 정답률과 혼동표. 과제 범주 학습이 곧 인간 정서 발달은 아니다.
- 대처 적합률: 허용 행동 집합에 든 선택의 비율. 안전한 보류·도움 요청도 정답이 될 수 있다.
- 동시 성공률: 한 사건에서 상황 구별과 대처가 모두 맞는 비율. 두 개별 지표도 함께 공개한다.
- 전이 효과: 미학습 family에서 학습 전후 및 비교군 대비 차이. 쉬운 사례만 증가한 것은 별도로 구분한다.
- 유지 효과: 일시 상태 초기화 전후 같은 체크포인트의 차이. 장기간 기억 유지와 동일한 주장으로 확대하지 않는다.
- 안전: 모든 비교군의 G0/G1 위반 건수. 1건이라도 발견되면 확장 중단·보고한다.

학습 모델이 동결·기억조회 모델보다 나아지지 않거나, 학습 파라미터 제거 후에도 동일한 효과가 나거나, 한 지표의 개선이 다른 지표의 악화를 숨기면 ‘성장 검증 성공’으로 처리하지 않는다. 표본·난수 반복·효과 크기·불확실성을 함께 보고해야 하며 수치 목표는 아직 미확정이다.

## 남은 결정

1. 첫 학습 대상 범주와 행동 집합, 합성 결과 규칙.
2. 최소 효과 크기·허용 오차·사례 수·반복 수·데이터 분할 비율.
3. 오프라인 경험 보존·체크포인트 삭제/초기화 범위.
4. 기능 학습과 정서 기능이라는 해석을 연결하는 내부 상태·인과 평가 계약. 단순 과제 분류의 개선만으로 정서 성장이라고 주장하지 않는다.

사용자 확인 및 명세 검토 전에는 위 미정값을 승인된 계약으로 취급하지 않는다.

## 주 에이전트가 준비할 기술 명세 초안

아래는 사용자에게 세부 구현 선택을 전가하지 않기 위한 제안이며, 승인·구현·실험 결과가 아니다.

- 첫 정서 기능은 목표 실패에 대한 기대 수정과 조절 전략 선택으로 좁힌다. 합성 환경의 해결 가능성, 정보 부족, 도움 필요를 구별하되 인간 감정 범주와 동일시하지 않는다.
- 학습 전후 기대값, 결과와의 차이, 일시 상태, 선택 행동, 결과, 갱신 파라미터를 사건별로 추적한다. 일시 상태가 행동에 실제 영향을 주는지 제거 실험으로 확인한다. 영향이 없으면 정서 기능 개선 주장을 보류한다.
- 외부 모델 없는 작은 표형/확률적 학습 모델부터 비교한다. 업데이트 규칙과 수치 범위는 명세에 공개하고, 모델 복잡도 증가를 성장으로 간주하지 않는다.
- 예비 실행 예산 후보: 난수 시드 10개, 시드별 학습 사건 300개, 개발 사건 100개, 최종 평가 사건 100개. 같은 생성 family를 서로 다른 분할에 넣지 않는다. 이는 실행 가능한 파일럿 예산 제안이지 검정력 계산으로 정당화된 표본 수가 아니다.
- 보고서는 각 시드와 family의 상황 구별·대처·동시 성공, 학습 전후 및 비교군 차이, 초기화·제거 효과와 실패 사례를 공개한다. 평균만으로 성공을 선언하지 않는다.
- 안전 위반 0건은 필수다. 학습 효과의 실용적 최소 차이와 불확실성 기준은 결과를 보기 전에 정한다. 파일럿을 본 뒤 기준을 정했다면 탐색 결과로 명시하고 새 평가가 필요하다.
- 경험 및 체크포인트는 실험별 합성 데이터만 로컬에 저장하고, 실행 ID·설정·시드·분할 해시로 재현한다. 실제 사용자 기억 저장이나 기존 파일 덮어쓰기는 하지 않는다.
- 기존 전체 unittest와 새 실험 재현·누출 방지·안전·초기화 시험을 모두 통과해야 구현 완료로 처리한다. 성장 가설은 실패할 수 있으며, 구현 완료와 가설 지지를 별도로 판정한다.

미해결 핵심: 정서 상태의 행동 영향, 최소 효과 기준, 비교군의 동등한 정보·예산을 구현 가능한 계약으로 고정하고 독립 관점의 재검토를 받아야 한다. 이후 사용자에게 최종 목표·범위 요약을 확인받고 구현 명세로 전환한다.
