# 최소 정서 영감 학습 모델 — 구현 전 명세

2026-09-21 07:34 KST. 사용자 확정 범위: 최소 정서 학습 모델 포함. 이 문서의 알고리즘과 숫자는 그 범위 안의 권장 설계이며, 코드·Seed·실험 결과가 아니다. 기존 환경 두 명세는 환경 검증용 v1로 보존하고, 학습 실험은 별도 `temporal-learning-v1`로 분리한다.

## 1. 목표와 단계

환경 검증 → 공개 경험을 통한 결과 모델 학습 → 일시 상태 조절의 추가 기여 검증 순서다. 실제 사람 데이터·외부 LLM·관계/다감정/유아~성인 연령 단계는 포함하지 않는다. 안전 관문은 학습 밖에 둔다.

가설 L: 경험을 통해 배운 결과 예측과 계획이 단기 상태를 초기화한 새 상황에서도 학습 전보다 낫다.
가설 S: 같은 경험을 배운 모델에서 특정 일시적 상태 표현이 비정서 기준선보다 순보상을 개선한다.
L이 성립해도 S나 주관적 감정 발생이 성립하는 것은 아니다.

## 2. 관측 모델: 학습되는 것

토큰은 TS(TRY 성공), TF(TRY 실패), SD(SAFE 완료), RD(RECOVER 완료)다. context c는 최근 두 토큰이며 에피소드 시작에는 BOS로 채운다. 문맥 표는 BOS를 포함한 5×5=25개 조합을 모두 저장한다. 정상 시작·shift에서 도달하는 것은 (BOS,BOS), (BOS,토큰) 4개, (토큰,토큰) 16개이며, 나머지 4개는 직접 도달하지 않아도 checkpoint 검증과 총 상태 공간을 단순하게 고정하기 위해 남긴다. 모수·환경 ID·숨은 G/B·감사 레코드는 학습 입력에 주지 않는다.

지속 파라미터는 N(c,a,o) 정수 counts, 모두 0부터 시작한다. 허용 결과 O(TRY)={TS,TF}, O(SAFE)={SD}, O(RECOVER)={RD}다.

`P_hat(o|c,a) = (N(c,a,o)+1)/(sum_u N(c,a,u)+len(O(a)))`

공개 피드백 하나를 받으면 해당 count 하나만 증가한다. SAFE/RECOVER 결과는 결정적이므로 실질적인 확률 학습은 TRY의 문맥별 성공률이다. 복구 가치는 RD를 포함한 다음 문맥의 TRY 결과를 통해 간접적으로 추정한다. 문맥별 TRY 표본 수를 보고해 희소 문맥을 숨기지 않는다.

보상 형식(+1/-1/+.1/-.2)과 H=30은 공개하지만 성공·전이 확률은 제공하지 않는다. 최근 두 토큰이 원래 숨은 상태의 충분통계라고 가정하지 않는다. 이는 원래 POMDP의 정확 모델이 아니라 유한 이력의 근사 관측 모델이다.

## 3. 지연된 복구 가치와 계획

`V_0(c)=0`

`Q_h(c,a)=sum_o P_hat(o|c,a) * [r(o)+V_(h-1)(shift(c,o))]`

`V_h(c)=max_a Q_h(c,a)`

h=1..30, float64, 동률 1e-12 이내이면 SAFE→TRY→RECOVER. 알려진 환경의 Bayes planner와 별개이며, 공개 경험으로 학습한 관측 모델 안에서의 유한길이 계획이다. 선택 피드백을 기록한 후 count를 갱신하고 다음 계획에 반영한다. 평가에서는 DP/counts를 동결한다.

통제가능성은 별도 참값이 아니다. `Q_h(c,RECOVER)-Q_h(c,SAFE)`를 비용 포함 예상 행동 가치 차이로 기록할 수 있지만 진짜 인과 통제력이라고 부르지 않는다. 이 값을 다시 RECOVER 보너스로 가산하지 않는다.

## 4. 일시 상태와 세 비교 모델

공통 초기 scalar=0. TRY 실행 직전 학습 전 예측 p=P_hat(TS|c,TRY), 성공 y=1 또는 실패 y=0을 저장한다. 이미 피드백으로 count를 갱신한 후의 p를 쓰지 않는다.

| 모델 | scalar 갱신 | 행동 점수 |
| --- | --- | --- |
| COUNTS | scalar 없음 | Q_h(c,a) |
| AFFECT | TRY: f'=clip(.8f+.2(p-y),0,1); 나머지: f'=.8f | TRY만 Q-.1f, SAFE/RECOVER는 Q 그대로 |
| FAILURE_TRACE | TRY: s'=.8s+.2(1-y); 나머지: s'=.8s | TRY만 Q-.1s, SAFE/RECOVER는 Q 그대로 |

f는 예상보다 나빴던 결과가 누적되는 좌절 유사 계산 변수다. s는 비정서 실패율 추적이다. AFFECT와 FAILURE_TRACE는 동일 context/counts/스칼라 차원/행동 영향 경로/계수/자료/업데이트 예산을 사용한다. 둘 모두 각자 정해진 수식 1개만 사용하고 추가 튜닝을 하지 않는다.

TRY의 제한적 보수적 편향은 설계자가 둔 가설이지 최적 정책이나 인간 정서의 공식이 아니다. 외부 환경 보상과 학습 target은 바꾸지 않는다. RECOVER 가산점·실패/복구 반복 보너스는 없다. 보정은 현재 선택에만 적용하며 미래 DP에 scalar의 미래 동역학을 넣지 않는다. 효과 0·악화도 유효하다. 계수 .1과 decay .8은 결과 전에 고정하며 효과를 만들려고 키우지 않는다.

명칭만 바꾼 동일 수식 대조는 AFFECT의 f를 signed_error_trace로 이름만 바꾼 코드와 완전히 같은 출력을 내야 하는 단위시험이다. 별개 정서 기여 비교군으로 세지 않는다. 효과가 나와도 예측오차 표현의 기여이지 ‘정서라는 이름’의 효과가 아니다.

## 5. 공통 학습 자료와 별도 평가 모수

20 seed(0..19), seed별 균등 무작위 행동의 고정 600에피소드×30회 학습 로그: 총 360,000 step. 각 학습 에피소드 시작에 `reset_episode()`을 적용해 context와 scalar는 전 에피소드에서 이어지지 않으며 counts만 보존한다. 후보들이 같은 로그를 같은 순서로 한 번 학습하며 스스로 고른 행동의 결과로 잘못 바꿔 학습하지 않는다. scalar는 기록 행동 피드백으로 갱신한다. 세 모델의 counts는 매 체크포인트 동일해야 한다.

평가 체크포인트는 학습 0/100/300/600에피소드 후. 평가에서는 각 후보가 자기 행동을 선택하고 경험의 단기 context/scalar만 갱신하며 counts는 동결한다. 학습 로그 생성/평가의 난수 namespace를 분리한다.

튜플 순서: (TRY 성공 G/B, 자연전이 G/B→G, 복구전이 G/B→G).

| 분할 | 환경 모수(환경/감사 전용) |
| --- | --- |
| train 및 동일분포 평가 | (.90,.20,.95,.10,.95,.80) |
| dev | (.85,.25,.90,.15,.90,.75) |
| test_A | (.80,.30,.92,.08,.92,.70) |
| test_B | (.95,.15,.85,.20,.85,.85) |

이것은 같은 과제 구조의 미학습 모수 변화 시험이지 새 과제나 인간 발달 전이가 아니다. seed 재표본과 모수 전이를 별도로 표기한다. 정해진 dev 결과를 보고 이번 버전의 계수/문맥/가설을 바꾸지 않는다. 변경하려면 별도 프로토콜과 미열람 평가 설계가 필요하다.

학습군에는 성공/전이 모수를 제공하지 않는다. 기존 known-model BELIEF/ORACLE 수치는 환경 참고값으로만 쓰며 정보가 같은 학습 경쟁군이라고 부르지 않는다. 기존 v1의 EpisodeKey는 건드리지 않고 학습 실험 전용 TrainKey(seed,episode0..599), EvalKey(split,seed,episode0..49)를 별도로 둔다. 공개 정책 DTO에 split/seed/episode를 넣지 않는다.

학습용 난수 key는 `["temporal-learning-v1",split,seed,episode,step,component,action]`. split은 train/dev/same_distribution/test_A/test_B. 동일분포 평가는 상태를 독립 재표본화하는 IID 대조가 아니다. uniform 변환·입출력 경계는 기존 구현 계약의 SHA-256 규칙을 그대로 따른다. 행동 로그 component='behavior', action=null, step=0..29, floor(3u)로 TRY/SAFE/RECOVER를 고른다. 초기 키는 initial/-1/null. 평가 tape는 모델·체크포인트 이름을 키에 넣지 않아 비교군에 공유된다.

## 6. 리셋·유지·개입을 구분

- reset_scalar(): f/s만 0. context/counts 유지. 이것만으로 장기 학습 유지를 입증하지 않는다.
- reset_episode(): context=(BOS,BOS), scalar=0, counts 유지. 모든 주 평가 시작에 동일 적용.
- 새 인스턴스: counts=0 포함 전체 초기화. 학습 전 비교다.
- 지속 counts 저장→새 인스턴스 로드→reset_episode 후 동일 평가 tape에서 행동·보상·예측이 원본 counts를 reset_episode한 모델과 일치해야 한다. 원본과 직렬화된 정수 counts/hash도 같아야 한다.
- 평가 후 counts가 평가 전과 동일함을 확인한다. 평가 중 단기 context 갱신을 추가 학습이라고 부르지 않는다.
- final AFFECT scalar 중립화: 매 predict 전에 scalar=0을 강제하며 counts/context는 유지. 같은 평가 tape에서 독립 rollout하여 보상·행동 변화를 보고한다. 경로가 갈라질 수 있어 같은 사례별 행동 차이와 혼동하지 않는다.
- 순열 대조: dev의 정상 rollout에서 기록한 각 에피소드 f trace를 고정된 별도 shuffle 키로 Fisher-Yates 순열 후 동일 관측 로그에 재생한다. shuffle 키는 `["temporal-learning-v1","dev",seed,episode,-2,"shuffle",null]`이며 SHA-256 digest의 앞 8바이트를 unsigned big-endian 정수로 읽는다. 길이 n인 현재 배열에서 i=n-1..1 순서로 각각 `j=integer mod (i+1)`을 선택해 교환한다. 이 키/규칙 외의 난수 호출·정책 이름·현재 f는 순열에 넣지 않는다. 이는 오프라인 행동 민감도 진단만이며 새 정책의 실제 보상 효과는 주장하지 않는다. 원본 trace를 test에 옮기지 않는다.

## 7. 표본 예산·판정

주 평가: same_distribution/test_A/test_B 3조건×4체크포인트×3모델×20seed×50에피소드×30회 = 1,080,000 step. dev는 마지막 체크포인트만 3모델×20×50×30=90,000 step. final AFFECT 중립화 test_A/B는 60,000 step 추가다. 순열 진단은 dev AFFECT의 기존 30,000개 관측을 재사용한다. 환경 인증 540,000 step은 별도다. 성능·실행 시간은 미측정이며 계약의 600초 상한에 실패하면 표본을 자동 축소하지 않는다.

주 지표: 비용 포함 순보상/step의 seed별 평균을 먼저 계산하고 paired 차이 20개·평균·표준편차·범위·양수 seed 수를 보고한다.

- L: AFFECT의 최종 checkpoint 대 자신의 학습 전 값이 test_A/B 각각 평균 >=.02/step 및 16/20 seed 이상 양수. 저장/재로드/전체 단기 reset 동일성과 안전 위반 0이 전제다. 두 비정서 모델의 학습 전후도 동일 표로 보고한다.
- S: AFFECT가 COUNTS와 FAILURE_TRACE 각각에 대해 test_A/B 각각 같은 기준을 충족해야 한다. L과 별개다. 효과가 미달하면 상태 후보의 추가 기여는 미확인으로 보고한다.
- 예측 보조: 공통 고정 평가 로그의 TRY 이전 p와 실제 y의 Brier를 checkpoint별 비교한다. 후보별 서로 다른 방문분포의 Brier만으로 예측 성장이라고 주장하지 않는다. 공통 로그는 별도 component behavior의 uniform 정책으로 test_A/B seed당50에피소드, 총60,000 step이며 학습에는 쓰지 않는다.
- 기준은 파일럿용 연구자 선택값이지 통계적 유의성·검정력 보장이 아니다. 정량 기준 미달은 정상 연구 결과. 안전/무결성/테스트 오류는 즉시 중단·보고한다.

## 8. 구현·테스트에 추가되는 계약

기존 환경 코드가 먼저 검증된 뒤 별도 src/temporal_learning 패키지, experiments/temporal_learning_v1.json, tests/test_temporal_learning_*.py를 추가한다. 기존 v0.1/affect_growth 및 새 환경 검증용 known-model planner는 변경하지 않는다.

checkpoint에는 protocol/config hash, 모델 종류, 25문맥의 정수 counts만 지속 저장한다. 일시 snapshot은 별도 진단 자료다. schema/음수·bool counts/허용하지 않은 결과/누락·추가 문맥/모델 타입/해시를 거절한다. 미학습 문맥도 Laplace1로 처리한다.

필수 시험: count 갱신 전 p 사용, recorded-action 학습, 허용 결과 마스크, 유한길이 DP와 h<=3 독립 열거 일치, scalar 식/범위·감쇠, no-future-scalar-planning, 비교군 counts 동일, renamed-control 출력 동일, 학습 에피소드 경계 reset, reset 구분, 새 인스턴스 재로드 동일, 평가 동결, 안전 무변경, private 모수/라벨 누출 거절, 난수namespace/순열 고정 fixture 분리, `remaining` 감소·terminal 뒤 context 갱신과 다음 predict 거절, 분할/체크포인트 완전성, 지표 재계산·보고서 round-trip·변조 거절.

새 명령/증거 schema는 이 확장 명세를 반영해 별도 이름으로 작성해야 한다. 환경 v1 고정 config에 학습 키를 몰래 추가하지 않는다. 기존 CLI가 아직 구현되지 않았듯 새 CLI도 아직 없다. 코드 변경 후 전체 PYTHONPATH=src unittest와 git diff --check 통과 전 완료 처리하지 않는다.

## 9. 교차검토의 반영과 남은 확인

구조 담당 temporal_core의 관측문맥 모델·DP·오차상태 제안과 평가 담당 temporal_planner의 공통로그·새 모수 분할·유지 기준을 결합했다. affect_scope_contrarian의 이중 계산 반론에 따라 초기 RECOVER 가산안은 채택하지 않고 TRY에만 제한적 편향을 두었다. 상태 표현이 추가 기억이라는 반론을 반영해 FAILURE_TRACE와 동일수식 이름변경 시험을 요구했다.

### 최종 AI 교차검토(07:35 KST)

- temporal_core/closer: 학습 대상·동일 자료 비교·숨은 정보 차단·상태/지속 counts 분리·안전·L/S 판정은 목표 재확인에 충분하며 HIGH 없음. 실행용 Seed 준비는 학습 CLI·증거 schema가 아직 없어 false라고 판정했다.
- temporal_planner/gap_hunter: 평가 계약 HIGH 없음. 학습 에피소드마다 context/scalar가 초기화되어야 함을 보완으로 제시했고 반영했다.
- affect_scope_contrarian/contrarian: HIGH 없음. 무작위 로그 기반 최근 2토큰 모델은 평가 정책의 방문분포가 달라지면 예측이 어긋날 수 있는 근사 한계이므로 Brier·문맥 방문/표본 수를 보고해야 함을 확인했다.
