## 상태

이 문서는 `temporal-learning-v2-20260923-02`의 S 미달 뒤 작성한 설계 초안이다. 2026-09-23 KST에 사용자는 정확한 환경·config·evidence schema, 격리 E2E, 그리고 bounded 정규 실행을 승인했다. 정규 실행 결과는 아래에 고정한다.

## 연구 질문

failure-rich held-out 환경에서 AFFECT의 scalar 기반 TRY 보정이 COUNTS, FAILURE_TRACE, 그리고 scalar-neutral AFFECT보다 reward/step을 높이는가?

이 질문은 실제 감정·의식·인간 발달을 묻지 않는다. 합성 환경에서 정의된 기능적 정책 차이만 검사한다.

## 고정할 설계 요소

- 새 protocol label과 새 run-id를 사용하며, 기존 v2 artifact/config/source hash는 변경하지 않는다.
- training environment, horizon 30, 학습 입력, 안전 allowlist, AFFECT scalar 식, tie-break 순서를 그대로 둔다.
- held-out은 현재 `test_A`/`test_B`와 다른 새 failure-rich split으로 정의한다. hidden-state 초기분포·전이·reward kernel·tape key namespace를 문서와 config에 고정한다.
- 독립 seed는 `20..39`로 고정한다. 이전 seed `0..19`와 결과를 합산하지 않는다.
- 모든 모델은 같은 seed/episode/tape를 공유한다. 평가 중 count는 동결한다.
- scalar-neutral AFFECT는 동일 checkpoint·tape에서 매 decision scalar를 0으로 강제하는 별도 대조로 취급한다.

## 수용·실패 기준

주 효과는 final checkpoint에서 AFFECT의 seed-aligned reward/step이 각각 COUNTS, FAILURE_TRACE, scalar-neutral AFFECT보다 높은가로 본다.

- 각 비교의 평균 paired delta가 `>= +0.02`
- 각 비교에서 20개 중 최소 16개 seed가 `>= +0.02`
- 위 세 비교가 모두 충족될 때만 이 새 split에서의 기능적 우월성 가설을 지지한다.

하나라도 미달하면 가설은 미지지로 기록한다. 기준, scalar 계수, seed, split, 모델 선택을 결과 뒤에 바꾸지 않는다.

## failure-rich 고정 환경 계약

- initial `P(G)=0.20`
- TRY success: `G=0.80`, `B=0.10`
- natural transition `P(next=G)`: `G=0.75`, `B=0.05`
- RECOVER transition `P(next=G)`: `G=0.90`, `B=0.65`
- tape key의 condition은 정확히 `failure_rich`다. 기존 `temporal-environment-v1` tape protocol은 바꾸지 않으며, condition 값이 독립 namespace를 이룬다.

## 구현 경계

`temporal_learning_followup`은 v2와 별도 artifact schema `temporal-learning-followup-1`을 사용한다. config loader는 train/failure-rich 조건, 30-step horizon, 기존 scalar 식·tie-break 상수와 네 비교 모델 목록을 고정한다. `affect_neutral`은 AFFECT checkpoint를 공유하되 매 판단 직전 scalar를 초기화하는 반사실 비교다.

## 필수 evidence와 중단 조건

- preflight는 public/persistence/diagnostic/counterfactual work를 분리 보고한다.
- run 뒤 strict public verify, restricted-audit verify, verify-first replay가 모두 exit 0이어야 한다.
- Brier·context TRY·neutral/permuted는 방향성 수용 기준과 분리된 진단 evidence로 기록한다.
- nonzero exit, missing terminal marker, completion/failure contract 위반, verify/replay failure가 있으면 해석 전에 중단한다.
