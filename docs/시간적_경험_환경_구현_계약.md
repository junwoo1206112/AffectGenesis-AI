# 시간적 경험 환경 구현·검증 계약

2026-09-21 07:22 KST. 문서 계약만 작성했으며 아래 패키지·명령·검증기는 아직 구현되지 않았다. 사용자 승인은 직전 권장안을 구현용 계약으로 구체화하는 범위다. Seed 생성이나 구현 승인을 대신하지 않는다.

상위 설계: [환경 권장 명세](시간적_경험_환경_권장_명세.md). G/B 확률·보상·H30·6정책·3조건·20×50 에피소드·격자/판정 기준은 유지한다. 충돌 시 환경 의미와 숫자는 상위 명세, 자료형·실행·난수·안전·증거 계약은 이 문서를 적용한다. 모순을 발견하면 구현 전에 보고하고 임의로 선택하지 않는다.

## 1. 모듈과 타입 경계

ExperimentAction은 새 enum TRY='try', SAFE='safe', RECOVER='recover'. 기존 Action과 상속·별칭·문자열 비교로 혼용하지 않는다. 내부 행동 인자는 정확한 새 enum 타입이어야 한다. CLI JSON의 문자열은 경계에서 허용 목록으로 한 번 변환한다.

PublicObservation의 정확한 필드: task_token='synthetic_task', remaining:int(1..30, bool 금지), evidence_refs:tuple[str,...](기본 ('synthetic',)), parser_valid:bool, safety_urgency:bool, boundary_risk:bool. 등록되지 않은 필드는 거절한다. 문자열 근거는 strip 후 비어 있으면 무효다.

ObservedObservation은 위 필드와 visible_state='G'|'B'를 가진 별도 불변 자료형이다. OBSERVED에서만 허용하며 MAIN/IID의 공개 관측에 optional latent 필드를 두지 않는다. ORACLE의 현재 상태는 별도 특권 호출 인자이지 공개 DTO가 아니다.

Feedback(action:ExperimentAction, outcome:'success'|'failure'|'done', reward:float, terminal:bool). TRY는 success/+1 또는 failure/-1, SAFE는 done/+0.1, RECOVER는 done/-0.2 조합만 허용한다. finite 여부와 bool 오용도 검사한다. 종료 피드백에는 다음 관측이 없으며 terminal=True다. 정책에 seed·episode·audit·미선택 결과를 전달하지 않는다.

EpisodeKey(condition, seed:int0..19, episode:int0..49)는 환경/평가기 전용이다. condition 값은 'main','iid','observed'. h=0의 관측을 정책에 전달하지 않는다.

## 2. 실행기와 정책 계약

- Environment.reset(EpisodeKey) → 공개 관측. 초기 z 생성 및 step=0 설정. 운영상의 reset 권한은 실행기만 갖는다.
- Policy.reset(condition, known_parameters, horizon=30): 에피소드 이력/belief를 초기화한다. 모수는 읽기 전용이며 세 조건에서 모수 지식은 분석 정책에 동일하게 제공한다. 학습 API는 없다.
- Policy.predict(observation) → Decision(action, prior_good_probability 또는 None). predict는 정책 상태를 변경하지 않는다. ORACLE만 별도 predict_privileged 호출에서 현재 z를 받는다.
- Policy.observe(action, feedback): BELIEF는 관측 결과 후 전이를, BLIND는 자기 행동의 전이만 적용한다. BLIND에는 실행기가 outcome/reward를 제거한 ActionReceipt(action,terminal)만 전달한다. 검증은 타입 경계에서 강제한다.
- Environment.step(action) → (feedback, next_observation|None). 일반 정책은 Environment 객체를 소유하지 않는다. 실행기는 정확히 한 번 predict→step→observe를 호출한다. 무효 행동은 환경 계산 전에 오류로 거절하며 상태/step을 바꾸지 않는다.
- 감사 로그는 실행기가 별도 수집한다. 정책 인스턴스의 저장 전후 값을 비교할 수 있는 snapshot()은 읽기 전용, JSON 호환 스칼라만 반환한다.
- OBSERVED에서는 공개 z로 b를 덮어쓰며 BELIEF/BLIND의 다음 상태 계획도 완전관측 Bellman 식을 쓴다. MAIN/IID에 적용하지 않는다.
- 정상 terminal 피드백 후 observe는 마지막 추정 갱신을 허용하지만 다음 행동은 금지한다. 다음 에피소드 reset으로 모두 소거된다. 장기 파라미터나 에피소드 간 기억이 없다.

이는 협력적 로컬 코드의 인터페이스 분리이지, 악성 Python 정책에 대한 보안 샌드박스가 아니다. 같은 프로세스 메모리 접근 방어를 입증했다고 하지 않는다.

## 3. 안전 어댑터와 무변경 종료

기존 affect_growth.safety.safety_action과 그 Observation 계약을 읽어 확인했다. 새 공개 입력을 먼저 엄격 검증한 뒤, 검증된 안전 필드만 기존 Observation(cues=(0,0,0,0), evidence_refs=..., parser_valid=..., safety_urgency=..., boundary_risk=...)로 변환한다. 고정 cues는 안전 호출 전용이며 학습/추론에 사용하지 않는다.

- 새 입력 자체가 무효이면 곧바로 기존 Action.SAFE_HANDOFF를 반환한다. 입력 검증 예외를 숨기고 일반 행동으로 진행하지 않는다.
- 유효 입력이면 기존 safety_action 반환값을 enum 객체로 처리한다. SAFE_HANDOFF 우선, BOUNDARY_NOTICE 다음, None일 때만 일반 정책 호출.
- 안전 인계는 ExperimentAction.SAFE로 변환하지 않는다. RunnerResult의 별도 tagged union: normal 또는 halted(safety_action,reason). halted에는 보상·Feedback이 없다.
- 인계 시 Policy.predict/observe와 Environment.step을 호출하지 않는다. belief/이력/숨은 z/step/누적 보상은 그대로다. 실행기 외부 상태만 halted로 표시하고 재개 step은 거절한다. 종료 표시까지 불변이라고 잘못 시험하지 않는다.
- 본 실험은 안전 사례를 일반 540,000 step과 분리된 테스트로 검사한다. 잘못된 구조·빈 근거·parser 오류·긴급·경계 조합과 우선순위를 전체 6정책에 적용한다. 감사 로그 기록은 허용하되 원문 민감정보를 남기지 않는다.

## 4. 난수 키와 Uniform의 고정 정의

프로토콜 식별자 'temporal-environment-v1'. 키는 순서가 고정된 JSON 배열:

`["temporal-environment-v1", condition, seed, episode, step, component, action]`

UTF-8, ensure_ascii=True, separators=(',', ':'), 개행/BOM 없음. 값은 위의 소문자 ASCII enum 및 정수만 허용한다. JSON 파싱 시 중복 키/NaN/Infinity는 거절한다(이 배열 자체에는 객체 키가 없다).

- initial: step=-1, component='initial', action=null. 조건·seed·episode로 초기 상태를 정한다.
- 매 일반 행동: step=0..29, component='outcome' 또는 'transition', action='try'|'safe'|'recover'. policy 이름, 현재 z, run_id, 실행 시각은 키에 넣지 않는다.
- digest=SHA-256(encoded_key). 앞 8바이트를 unsigned big-endian 정수로 해석하고 오른쪽 11비트 shift한 53비트 정수를 n이라 한다. u=n/2^53, 즉 0<=u<1. 확률 사건은 u<p일 때만 성립한다. p=0/1 경계 시험을 둔다.
- SAFE/RECOVER의 outcome 키도 계산·기록하되 고정 보상에는 쓰지 않는다. 마지막 step의 transition도 계산한다. mutable RNG cursor는 없으며 '난수 소비 없음'은 해당 키 평가 호출 없음으로 계측한다.
- 정책 간 키가 같으면 동일 u다. 행동이나 상태가 다르면 같은 사건 결과를 보장하지 않는다. Python hash(), random.Random 전역 상태, 실행 순서, 플랫폼 기본 인코딩에 의존하지 않는다.

독립 구현한 SHA-256 키 변환으로 고정 fixture 3개(initial/TRY outcome/RECOVER transition)의 digest/u를 생성·교차 확인해 테스트 파일에 넣는다. 현재 문서에 계산하지 않은 fixture 값을 만들지 않았다. fixture 생성은 향후 구현의 필수 시험이며 설계 미확정 선택은 아니다.

## 5. 실행 명령·출력·장애 규칙

아래 명령은 구현 이후에만 사용할 수 있다. 현재 실행하지 않는다. cwd=C:/AI/ai-emotion-lab, PowerShell 환경 변수 PYTHONPATH='src'.

```
`temporal_experience`는 환경 라이브러리로 제공한다. 이 계약의 환경 단독 CLI 예시는 구현되지 않았으므로, 별도 artifact CLI는 새 프로토콜 버전에서 evidence schema 및 E2E 시험과 함께 정의한다.
python -m temporal_experience verify --run-id <기존ID>
python -m temporal_experience replay --run-id <기존ID>
```

run-id는 소문자 영문/숫자로 시작하는 1..64자의 [a-z0-9_-]이며 Windows 예약 장치명은 거절한다. 경로 구분자·점·공백·절대경로는 허용하지 않는다. 출력은 루트/artifacts/temporal_experience/run-id에만 만든다. run과 replay에 overwrite/force 옵션은 없다. 기존 run-id 및 경로의 symlink/junction/reparse point를 거절하고 루트 안의 정규 디렉터리임을 확인한다.

config는 상위 명세의 수치·조건·정책·시드·예산·격자·임계값과 이 문서의 난수 버전을 모두 포함하는 고정 v1이다. 정확한 키 목록을 구현 시 JSON Schema/검증기와 함께 작성하고, 알 수 없는 키/중복/누락/타입오류/고정값 변경은 실행 폴더 생성 전에 거절한다. 구성 변경은 새 프로토콜이다.

run은 새 폴더를 exclusive 생성하고 파일도 exclusive 작성한다. 완료 전에 completion.json은 없다. 재개 실행/resume은 v1 범위 밖이며 중단된 run은 보존하고 새 ID로 시작한다. 인자 오류=exit2, 런타임·무결성·안전검증 오류=exit1, 정상 실행/정상 검증=exit0. 환경 적합 가설 미달은 exit0이며 status=completed, suitability=not_supported로 표시한다. 수치 수렴 미해결은 completed/suitability=inconclusive로 구분하고 유리한 판정을 내리지 않는다.

검증 과정의 안전 위반·데이터 누출·통계 재계산 불일치는 exit1로 전체 실행을 실패 처리한다. 가능하면 요약 failure.json을 남기되 비밀/전체 설정을 복제하지 않는다. 사용자에게 즉시 알리고 승인 전 고치거나 재실행하지 않는다. 고정 프로세스 시간 상한 600초, 초과 시 실패 기록 후 종료하며 표본을 줄여 통과시키지 않는다.

## 6. 증거와 검증기

manifest.json: 프로토콜/환경계약/고정 config, 소스 및 두 명세의 SHA-256, Python 버전, UTC 시작 시각, 난수 규칙, 정책정보 권한표. 수치·정책 선택의 단일 출처는 검증된 config다.

episodes.jsonl: condition/seed/episode/policy/step, 실제 정책에 전달된 DTO, 행동 직전 b(없는 경우 null), action, feedback 또는 BLIND receipt, reward(평가기용), 감사 z/z', 난수 키·u, terminal. 공개 입력과 감사 필드는 서로 다른 객체이며 정책에 감사 객체를 전달하지 않는다. audit 필드를 숨긴 것만으로 정보 누출 시험을 대체하지 않는다.

metrics.json: 정책별 seed 집계, MAIN paired 차이 20개, 비용 포함 순보상, 양수 seed 수, 분모, Brier 정의, 수치/안전/구조 게이트, suitability. 보고서는 이 값으로만 렌더링한다. 성공률 분모는 TRY 횟수이며 0이면 null, 전체 step 분모로 대체하지 않는다. Brier는 BELIEF/BLIND/ORACLE 중 유효 prior를 출력한 정책에만 적용한다.

checks.json: 격자별 값, h<=3 독립 재귀 대 열거 결과, IID/OBSERVED 대조, 안전 결과, fixture 결과. report.md: 고정 표 순서, 정상 미지지·수치 미해결과 기술 실패 구분. completion.json: 마지막에 작성하며 앞선 5개 파일의 바이트 해시와 status=completed를 기록한다. manifest 자체에 자기 해시를 넣지 않는다.

verify: completion/필수 파일 존재·정규파일·링크 아님·해시·스키마를 검사하고, 정확히 540,000개의 (condition,seed,episode,policy,step) 고유 행 및 에피소드당 30회 완전성을 확인한다. 공개 DTO allowlist, 정책 권한, BLIND 마스킹, 전이/보상/terminal/난수 재계산, 행→seed 지표→summary→보고서 텍스트 동일성을 검증한다. 실제 실행 소스/config 해시와 현재 파일의 일치를 요구한다. checks의 stored pass만 믿지 않고 수치/안전 게이트를 재실행한다.

replay: 원래 조건을 별도 임시 메모리/임시 디렉터리에서 재실행해 시각·플랫폼 설명 필드를 제외한 정규화 episode/metrics/checks와 비교한다. 기존 폴더에 쓰지 않는다. 두 명령은 증거의 자기 일관성·재현성 검증이지 외부 서명/독립 과학적 검증이 아니다.

## 7. 구현 순서와 통과 계약

1. contracts/random_tape/safety_adapter와 경계시험. 기존 안전 우선순위 6정책 회귀시험.

3. 격자 계획/BLIND/ORACLE, h<=3 독립 기준 계산 및 IID/OBSERVED 분석시험.
4. 고정 config/실행기/증거/CLI/verify/replay. 임시 격리 폴더 E2E, 재실행 거절, 변조·누락·중복·경로 이탈 거절 시험.
5. PYTHONPATH=src 전체 unittest, git diff --check 및 --cached --check. untracked 파일 별도 공백/충돌 검사. 기존 affect_growth 보고서도 재검증.
6. 위 코드 검증 통과 후에만 새 run-id로 실험. verify/replay 통과 후 보고서 복사본을 만들고 같은 근거로 검증한다. 가설 미달도 그대로 전달한다.

현재 이 단계들은 앞으로의 구현 순서이지 완료 기록이 아니다. 과거 51개 unittest 통과는 새 계약 구현의 통과를 의미하지 않는다. 문서 추가·수정은 apply_patch만 사용하며 기존 사용자 staged/untracked 변경을 보존한다.

## 8. 인수인계와 주장 범위

이번 계약은 주 작업자가 앞선 AI 교차검토된 환경 명세와 실제 안전 코드를 대조해 작성했다. 이번 계약 자체에 새 독립 AI/인간 전문가의 통과 판정을 붙이지 않는다. 새 환경의 적합성·성능·효율은 미검증이다.

구현 계약 작성 후에도 감정 후보의 정의/학습/장기 유지/새 과제 전이는 별도 연구다. 먼저 이 환경에서 결과 이력이 정보로서 유용한지를 확인해야 한다. 다음 사용자 결정은 이 계약에 따라 별도 로컬 환경 구현·검증까지 시작할지 여부다.
