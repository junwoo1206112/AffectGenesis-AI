1. python -m unittest discover -s tests -v → 46개 OK, 종료 코드 0.
2. python -m affect_growth --config experiments/growth_v0_2.json --run-id pilot-20260920-01 → 약 10초, 종료 코드 0.

실행 산출물은 artifacts/affect_growth/pilot-20260920-01/에 보존했다. completion.json은 실험 프로그램의 종료를 뜻하며 후속 보고서 검증 통과를 뜻하지 않는다. docs의 최종 비교 평가 보고서는 아직 작성하지 않았다.

## 확인한 원인 후보

render_report는 contrasts 딕셔너리의 삽입 순서대로 표를 출력한다. 실행 시 표 순서는 pre → frozen → memory인데, canonical JSON 저장은 sort_keys=True이므로 metrics.json을 다시 읽으면 frozen → memory → pre가 된다. 동일 지표라도 재생성한 표 순서가 달라 최종 문자열 비교가 실패하는 것이 유력하다.

오류 후에는 원본 보고서와 저장된 키 순서만 읽어 확인했다. 수정이나 재실행은 하지 않았다. 원본 보고서의 수치는 검증 미완료 결과이며 확정 연구 결론으로 전달하지 않는다. 원본에 학습 가설 지지가 표시되어 있어도 전체 작업 완료 또는 실제 감정 발생의 근거가 아니다. 정서 상태의 행동 변화율은 원본에서 0으로 표시되므로 학습 효과와 정서 기능의 기여를 혼동하면 안 된다.

## 재개 방법 — 사용자 승인 후

1. 렌더링의 비교 순서를 명시적 고정 순서로 바꾸고, 직렬화·역직렬화 후 보고서 동일성을 검사하는 시험을 추가한다.
2. 검증 명령 실패를 포착하는 CLI end-to-end 시험을 추가한다. 단위시험만으로 보고서 경로를 검증한 것으로 처리하지 않는다.
3. 전체 unittest, untracked 파일 포함 공백/충돌 검사, git diff --check를 실행한다.
4. 기존 run을 덮어쓰지 않고 새 run_id로 실행한다. 원천 코드 해시가 달라지므로 과거 산출물을 새 코드에서 통과시키려고 변조하지 않는다.
5. --verify-report가 통과하면 실제 결과를 docs/감정_성장_비교_평가_보고서.md로 전달하고 다시 검증한다. 가설 지지와 구현 검증을 별도로 보고한다.

로컬 명세 QA의 NONE 출력 표시는 seed-architect의 공식 ‘출력 문자열 검사 없음’ sentinel이다. 이를 종료 코드 문장으로 바꾸자는 QA 제안은 형식 계약과 맞지 않아 적용하지 않았다. 파일 보존 증거 보강은 위의 실제 해시 비교와 별도 기록으로 수행했다.
