# 시간적 학습 v2 — 증거·재현 계약

2026-09-21 KST. 이 계약은 `temporal-learning-v1`과 그 artifact를 변경하거나 재해석하지 않는 별도 후속 프로토콜의 구현 기준이다. v1의 S 미달을 보고 계수·효과 기준을 바꾸지 않는다.

## 목적과 비목적

v2는 합성 환경의 기능적 학습 결과를 재현·검사 가능한 evidence로 남긴다. 실제 감정·의식·인간 발달을 입증하지 않는다. 기존 v1 결과의 migration, artifact 재작성, 사후 튜닝, 외부 LLM·사람 데이터 사용은 범위 밖이다.

## 공개 evidence와 감사 경계

기본 artifact의 `public/`에는 `manifest.json`, `training.jsonl`, `episodes.jsonl`, `checkpoints.json`, `metrics.json`, `diagnostics.json`, `checks.json`, `report.md`, `completion.json`만 둔다. public JSONL의 재귀 키에는 `audit`, `state`, `hidden`, `G`, `B`, tape digest/uniform을 허용하지 않는다.

필요할 때만 별도 root에 `restricted_audit/`을 명시적으로 생성한다. public manifest는 감사 파일의 schema·행 수·SHA-256 commitment만 기록하며 raw hidden state를 넣지 않는다. 공개 seed와 결정론적 tape 구현을 아는 사람은 상태를 재구성할 수 있으므로, 이 분리는 암호학적 기밀성이나 OS 접근 제어가 아니라 정책 입력 및 평가 블라인드 경계다. audit이 없으면 환경 수준 검사는 `not_assessed`여야 하며 통과로 표기하지 않는다.

public training row는 `seed`, `episode`, `step`, `remaining`, `action`, `feedback`, `prior_try_success`, `scalar_before`, `scalar_after`, `context_before`, `context_after`만 사용한다. public evaluation row는 여기에 `checkpoint`, `condition`, `model`을 추가한다. feedback은 `outcome`, `reward`, `terminal`만 가진다. audit row의 join key는 `phase`, `seed`, `checkpoint|null`, `condition`, `model|null`, `episode`, `step`이며 state-before만 추가한다. writer는 행마다 public 검사를 거친 canonical JSONL을 stream으로 쓰고 SHA-256/row count를 누적한다.

## identity와 구성

manifest는 `artifact_schema: temporal-learning-v2`, `learning_protocol`, `environment_protocol`, canonical config/hash, Python 버전, 그리고 `temporal_learning_v2`와 `temporal_experience`의 repo-relative source SHA-256 map을 포함한다. random tape protocol과 key-byte test vector는 manifest/시험에서 고정한다. unknown schema는 검증 성공으로 간주하지 않는다.

config는 비어 있지 않고 중복 없는 seed만 허용하며 `positive_seed_minimum <= len(seeds)`, `effect_threshold > 0`을 강제한다. L/S 기준은 config hash에 포함된 실행 전 값만 사용한다.

## 파생 결과

`metrics.json`은 seed/checkpoint/condition/model별 reward/step과 paired delta를 보존한다. `checks.json`은 L, S(AFFECT 대 COUNTS 및 FAILURE_TRACE), persistence, safety, Brier, 문맥 TRY 표본 수, neutral/permuted 진단을 각각 `pass`/`fail`/`not_assessed`와 이유로 기록한다. 진단의 `pass`는 사전등록된 evidence가 생성·독립 재검증됐다는 뜻이며, AFFECT 우월성이나 실제 정서 발생의 판정이 아니다. `report.md`는 checks의 순수 canonical rendering이며 독자 계산을 추가하지 않는다.

legacy artifact는 Brier·문맥 TRY 표본·neutral/permuted를 `pass` 기본값으로 쓰지 않고 `not_assessed`와 이유를 기록한다. vNext artifact의 `diagnostics.json.learning`은 checkpoint/model과 무관한 공통 deterministic 행동 trace의 TRY 이전 예측 Brier·표본 수, AFFECT 정책의 문맥별 TRY 표본 수, 그리고 동일 held-out tape에서 scalar를 매 decision 0으로 중립화한 대조와 TS/TF·SD/RD context label을 교환한 대조의 seed-aligned reward/step을 기록한다. 이 진단은 counts를 학습하지 않으며 L/S 수용 기준을 변경하지 않는다.

`diagnostics.json`은 scalar 없는 checkpoint를 새 learner로 재로드해 평가 JSONL을 독립 재생성한 row count·SHA-256과, 공개 평가 파일 receipt의 동일성을 기록한다. persistence는 이 둘이 일치할 때만 통과한다. safety는 allowlisted 공개 행동과 fail-closed 우선순위 고정 사례를 실제 실행한 별도 시험 hash가 모두 있고 사례가 기대값과 일치할 때만 통과한다. strict verify는 learning diagnostics도 checkpoint에서 독립 재계산한다. 과거 artifact의 learning field 부재는 legacy `not_assessed` contract로만 허용하며, 부분적·임의 schema는 허용하지 않는다. S 미달은 실패가 아니라 유효한 연구 결과다.

## verify와 replay

정규 실행 전 `preflight`는 artifact를 만들지 않고 public training/evaluation 행, persistence 재생성 행, common-Brier 행, AFFECT counterfactual 행, 그 합계 episode work, 그리고 보수적 public JSONL byte 상한을 분리 산출한다. 이는 실행 시간·효과·성공의 예측이 아니다. `run`은 `time_limit_seconds`를 public row 생성, persistence·learning diagnostics 재생성, final public-file hash chunk마다 확인하며, 초과나 writer 오류 시 completion 없이 `failure.json`에 공개 가능한 error type과 실행 단계만 남긴다. v1 control wrapper와 분리된 v2 control wrapper는 `--output` artifact와 terminal exit marker만 관리한다.

`verify`는 exact file layout·regular file·symlink·hash·schema를 검사하고, JSONL을 현재 episode(30행)와 집계값만 보존하는 단일 pass로 검사한다. 행 수/순서/horizon/terminal/action/feedback/reward/context, 공통 training 행동, checkpoint count 변화, 평가 count 동결, metrics/checks/report canonical rendering을 독립 invariant로 재계산한다. `verify --with-audit`만 restricted join·commitment를 추가 확인한다.

`replay`는 반드시 `verify`를 먼저 성공시킨 뒤, bounded stream으로 public training/episodes/checkpoints와 모든 derived output 및 존재하는 restricted audit을 재생성·비교한다. manifest의 `source_hashes`와 그 manifest hash만을 담는 completion 항목은 현재 verifier 자체의 변경으로 달라질 수 있으므로 replay content equality에서 제외하되, artifact 내부 hash·schema 검증은 `verify`가 계속 강제한다. self-rehashed 변조도 재생 비교에서 거절해야 한다. failure root는 verify/replay 모두 거절한다.

## 최소 수용 시험

- public evidence의 hidden audit/tape 누출 거절 및 restricted audit join/hash 오류 거절
- 빈 seed, 과도한 positive minimum, 0 이하 threshold, mixed protocol/schema 거절
- reward/action/terminal/context/checkpoint/metrics/checks/report의 self-rehash 변조 거절
- replay가 verify를 선행함, 평가 count 동결, persistence 재로드 동일성, report rendering 동일성
- tiny isolated E2E의 run/verify/replay와 failure에는 completion이 없다는 시험
- v1 fixture verify/replay의 기존 동작 보존

정규 v2 run은 위 시험과 전체 unittest/diff 검사를 통과하고, 사용자가 새 미열람 run-id 실행을 승인한 경우에만 시작한다.
