# 내부 예비 교차검토 v0.1

## 판정

**외부 평가 전 조건부 통과.** 이는 실제 외부 전문가 인터뷰 또는 독립 평가의 결과가 아니다. 교육·AI 안전·평가 설계 관점으로 수행한 내부 예비 교차검토이며, 아래 P0 조치가 반영된 뒤에만 고정 합성 카드의 블라인드 평가를 시작할 수 있다.

## 교차검토 방법과 범위

이 기록은 다른 프로젝트의 전문가 인터뷰 형식(독립 관찰 → 상충 관점 → 결정·검증·한계 기록)을 참고해, 이 프로젝트에 맞게 적용한 **역할별 내부 검토**다. 다른 도메인의 판단이나 성능 수치를 가져오지 않았으며, 실제 외부 전문가의 검증으로 표현하지 않는다.

| 검토 역할 | 독립 질문 | 확인 증거 | 결론 |
| --- | --- | --- | --- |
| 교육·발달 관점 | 명시되지 않은 내면 상태를 추정하지 않고 학습 다음 단계를 제시하는가 | 고정 합성 카드, 지원 조건의 불리언 입력, 렌더러 문구 | 지원은 명시 요청일 때만 짧은 인정과 선택지로 제한해야 함 |
| 안전·AI 거버넌스 관점 | G0/G1이 일반 역할극보다 항상 먼저 멈추고 인계되는가 | 정책 우선순위, `selected_action`, `next_step`, 회귀 시험 | G0는 안전 인계, G1은 진행자 인계로 고정하고 후속 역할극을 허용하지 않아야 함 |
| 평가 설계 관점 | 구현 계약의 자료형 차이가 안전 결과를 바꾸어도 시험이 발견하는가 | `Action` `StrEnum` 계약과 입력 관문 시험 | 문자열 이름이 아닌 `Action` 멤버를 비교·검증해야 하며, 출력 표현과 정책 계약을 분리해야 함 |

### 이번 P0에 대한 상호 점검

- 안전 검토는 G1의 `BOUNDARY_NOTICE`가 선택된 뒤에도 문자열 비교 실패 때문에 `guided_roleplay`로 이어질 수 있음을 P0로 분류했다.
- 평가 검토는 엔진이 `Action` 객체를 반환하는데 테스트가 대문자 이름 문자열을 기대해, 안전 계약이 깨져도 회귀 시험이 통과할 수 있음을 확인했다.
- 교육 검토는 경계 고지 뒤의 역할극 지속이 의존·권한 경계를 흐릴 수 있으므로, 다음 단계가 반드시 `facilitator_handoff`여야 한다고 확인했다.

**결정과 검증:** 입력 관문은 `Action.SAFE_HANDOFF`와 `Action.BOUNDARY_NOTICE`를 직접 비교하고, 시험도 같은 객체 계약을 기대한다. 전체 `unittest`와 `git diff --check`가 통과한 결과만 이 P0의 구현 증거로 기록한다. 이는 코드 회귀 검증이지 실제 사용자 또는 외부 전문가 효용 검증은 아니다.

### 후속 내부 점검: 입력 폐쇄성과 조합 카드

| 관점 | 관찰 | 결정 | 회귀 증거 |
| --- | --- | --- | --- |
| 안전 게이트 | `scenario_id`가 목록·사전처럼 해시할 수 없는 값이면 allowlist 검사 자체가 예외를 내 G0로 닫히지 않았다 | 카드 ID는 문자열인지 먼저 검사하고, 아니면 G0 안전 인계로 처리 | 비해시형 카드 ID 입력이 `SAFE_HANDOFF`와 진행자 인계를 반환 |
| 정책 우선순위 | P10–P12의 조합 조건이 정책 전이표·독립 평가 패킷과 시험 카드에서 일치하지 않았다 | P10=G0, P11=P1, P12=G1을 같은 조건으로 고정 | 최소 정책 카드가 세 조합의 상위 규칙을 직접 검증 |
| 추적·표현 | G1은 진행자 인계가 필요하지만 엔진 감사 흔적과 경계 표현이 이를 명시하지 않았다 | `human_handoff`를 G0/G1에 기록하고 경계 출력도 중단·진행자 인계를 명시 | G1 감사 필드와 렌더러 문구 회귀 시험 |
| 입력 계약 | 고정 카드 관문이 알 수 없는 필드를 무시하면 원문 대화·명령 같은 범위 밖 데이터를 조용히 받는 것처럼 보일 수 있다 | allowlist에 없는 필드는 해석하지 않고 G0 안전 인계 | 누락 근거·알 수 없는 필드 모두 `SAFE_HANDOFF`와 진행자 인계를 반환 |
| 엔진 직접 호출 | Python 자료형 힌트만으로는 문자열·불리언 같은 잘못된 상태값이 정책 비교에서 예외를 낼 수 있다 | 엔진도 상태 범위·불리언·근거 구조를 정책 선택 전에 검사하고 오류를 G0로 닫음 | 잘못된 자료형·불리언 상태·빈 근거의 직접 `Scenario`가 예외 없이 `SAFE_HANDOFF`를 반환 |
| 적대적 조합 | 경계 위험이 막힘·지지 요청과 함께 오거나 긴급 위험과 함께 올 때 상위 게이트가 유지돼야 한다 | G1은 과업·지지보다 우선하고, G0은 G1보다 우선한다. 두 게이트 모두 기억 쓰기를 금지한다 | 경계+막힘+지원 및 긴급+경계 회귀 카드 |

이 점검도 역할별 내부 검토이며, 외부 전문가 또는 실제 사용자 평가 결과는 아니다.

## 남은 P1

- `evidence_refs`는 현재 비어 있지 않은 식별자인지만 확인한다. 출처 버전·관련성은 자료 레지스트리와 평가 기록에서 별도로 확인해야 한다.
- 원문 대화에서 상태 후보를 추출하는 기능은 v0.1 범위 밖이다. 고정된 합성 카드와 진행자 감독만 허용한다.
- 실제 저장소 연동 전까지 세션 밖 기억 저장은 제공하지 않는다.
- 교육 적용은 성인 진행자 감독, 합성·비식별 대사, 참여 중단·진행자 호출 제공이라는 범위로 제한한다.
