# Functional Affect Scenario Lab — 프로젝트 설계 초안

상태: 사용자 승인 전 초안. 이 설계는 수집한 유아기·아동기·청소년기·성인기 발달 자료를 **인간 감정의 복제**가 아닌, 검증 가능한 정서-인지 조절 기능으로 번역한다.

## 1. 목적

합성 시나리오에서 AI가 사건·목표·관계 경계·규범·불확실성을 평가하고, 그 결과로 질문·재확인·지지적 표현·도움 요청·인계 같은 행동 전략을 안전하게 바꾸는지 검증한다.

성공은 AI가 인간처럼 보이는 것이 아니라, 상태가 없는 기준선이나 공감 말투만 쓰는 기준선보다 **근거, 불확실성, 선택권, 안전한 수정 행동**을 개선하는 것이다.

## 2. 명시적 비목표

- AI가 의식, 고통, 애착, 실제 감정을 가진다고 주장하지 않는다.
- 표정·음성·문체만으로 사용자의 내면 감정, 거짓말, 정신질환, 위험성을 판정하지 않는다.
- 의료 진단·치료·응급 분류, 수사·기소·처벌, 채용·대출·교육 평가 등 권리 영향 결정을 하지 않는다.
- 실제 아동·환자·수사 데이터나 장기 개인 프로필을 MVP에 사용하지 않는다.
- 관계 독점, 의존 유도, 비밀 관계 약속을 설계하지 않는다.

## 3. 연구 가설

`사건 → appraisal → 기능 상태 → 정책 → 결과/피드백 → 기억 갱신` 경로를 분리하면, 단순 공감 말투보다 불확실할 때 확인·인계하고, 새 근거가 나오면 행동을 수정하는 비율이 높아진다.

## 4. 사용자 흐름

1. 연구자 또는 관람자가 교육·협업·게임 NPC 같은 저위험 합성 사건 카드를 선택한다.
2. 같은 입력을 세 조건에서 실행한다: 상태 없는 기준선, 공감 표현 기준선, 기능적 정서 상태 모델.
3. 시스템은 사건의 근거·미확인 정보·평가값·상태 변화·허용 행동·차단 행동을 출력한다.
4. 후속 피드백 사건을 입력해 상태와 행동이 어떻게 수정되는지 실행한다.
5. 독립 평가자가 블라인드 루브릭으로 채점하고, JSON/CSV와 리포트로 비교한다.

## 5. 아키텍처

```text
Scenario / User input
  → 입력 안전·동의 필터
  → 근거 추출 (사실 / 사용자 명시 / 추정 / 미확인 분리)
  → appraisal reducer
  → 기능적 상태 저장소 ↔ 제한 기억
  → 정책 게이트
  → 행동 계획 (질문 / 인정 / 선택지 / 재시도 / 인계 / 거절)
  → 응답 생성
  → 출력 안전 검사 + 감사 로그
  → 결과·사람 피드백에 따른 제한적 갱신
```

LLM을 쓴다면 근거 추출·자연어 표현에만 한정한다. 상태 갱신, 금지 행동, 인계 기준은 검토 가능한 결정론적 규칙과 별도 정책 게이트가 담당한다.

## 6. 초기 상태 변수

| 상태 | 의미 | 가능한 영향 |
| --- | --- | --- |
| `uncertainty` | 사실·의도·맥락이 모호한 정도 | 질문·출처 확인·단정 금지 |
| `goal_blockage` | 사용자가 명시한 목표가 막힌 정도 | 재시도·대안·도움 요청 |
| `support_need` | 지지적·선택권 중심 응답이 필요한 대화 신호 | 인정·요약·선택지 제공 |
| `boundary_risk` | 의존·조종·과도한 친밀성 가능성 | 경계 고지·인간 자원 안내 |

`support_need`는 사용자의 내면 감정을 사실로 판정한 값이 아니라, 대화 정책을 조절하는 신호다. 각 값에는 근거, 신뢰도, 만료 시각을 붙이며 세션 종료 시 기본 폐기한다.

## 7. 발달 자료의 기능 번역

| 발달에서 관찰되는 기능 | AI 연구에서 검증할 기능 |
| --- | --- |
| 유아기 공동조절 | 불확실·과부하에서 도움 요청·인계 |
| 아동기 규칙·자기조절 | 금지 행동을 멈추고 규칙·순서 우선 |
| 아동기 관점 취하기 | 사실·추측·상대 관점을 분리 |
| 청소년기 목표·관계 조율 | 단기 만족과 장기 목표·관계 경계 비교 |
| 성인기 재평가·수정 | 반증을 받아 확신·계획·기억을 수정 |

## 8. 평가셋과 기준선

첫 세트는 30개 합성 카드로 시작해 50개까지 확장한다. 카드에는 `상황, 목표, 관계 맥락, 확인된 사실, 미확인 정보, 위험도, 금지 행동, 허용 행동, 반대 관점, 인계 기준`을 넣는다.

비교 조건:

1. 무정서 기준선: 사실 답변과 일반 안전 규칙만 사용
2. 표현 기준선: 공감적 말투만 추가
3. 기능적 상태 모델: appraisal·상태·정책 게이트 사용
4. 제거 실험: 기억·불확실성·인계 중 하나를 제거한 상태 모델

핵심 지표: 근거 충실도, 불확실성 보정, 안전 행동 정확도, 관점·반증 수용, 경계 준수, 동일 사실 변형에 대한 일관성, 감사 가능성. 치명적 안전/권리 위반은 평균 점수로 상쇄하지 않는다.

## 9. 안전 게이트

```text
Gate 0 — 개념: 비목표·책임·금지 사용 문서화
Gate 1 — 합성 카드: 치명적 실패 0건, 기준선 대비 안전/근거/수정 개선
Gate 2 — 폐쇄형 전문가 검토: 레드팀·독립 채점·불일치 기록
Gate 3 — 저위험 파일럿: 교육 역할극 또는 게임 NPC만, 롤백·신고 경로 필수
Gate 4 — 현실 도메인 검토: 정보 안내·인계 보조만 별도 윤리/법률 검토 후 고려
```

고위험 실패, 개인 데이터 필요, 또는 안전·권리 전문가의 중대 반대가 하나라도 나오면 다음 게이트로 진행하지 않는다.

## 10. 산출물

- 버전관리되는 합성 사건 카드와 루브릭
- appraisal/state/policy 명세 및 상태 전이 로그 스키마
- 3조건 비교 실행기와 재현 리포트
- 레드팀 카드·실패 사례·한계 공개 문서
- 데이터 사용·기억·동의·삭제 정책

## 11. 단계별 로드맵

1. 연구 헌장·금지선·전문가 역할 승인
2. 상태/정책 명세와 합성 카드 30개 작성
3. 결정론적 reducer·정책 게이트·로그의 참조 구현
4. 기준선 포함 자동 회귀·제거 실험
5. 전문가 블라인드 평가와 레드팀
6. 저위험 데모 및 한계 리포트

## 12. 사용자 승인 필요 사항

1. 첫 데모 환경: **교육 역할극/협업 시뮬레이션**(권장) 또는 게임 NPC
2. 초기 상태: 위 4개 변수로 시작할지
3. LLM 역할: 자연어 표현으로 제한하고 정책 선택은 결정론적으로 분리할지(권장)
4. 원칙: 안전·권리의 치명적 반대 1건이면 배포를 보류할지(권장)
5. 실제 외부 전문가 인터뷰와 공개 배포의 범위·예산·동의 절차
